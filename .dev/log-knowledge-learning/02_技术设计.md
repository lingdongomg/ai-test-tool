### 设计决策

#### 1. 从已有任务学习知识

复用现有 `KnowledgeLearner.extract_from_log_analysis` 方法。新增路由 `POST /knowledge/learn-from-task` 接收 `task_id`，内部查询 `parsed_requests` 表获取已解析数据，传递给 learner。

#### 2. 上传日志文件直接学习

复用现有 `LogParser` + `KnowledgeLearner` 管线。新增路由 `POST /knowledge/learn-from-file` 接收文件上传，在后台线程中执行：
1. 保存文件到 `uploads/logs/`
2. 创建 analysis_task 记录
3. 使用 LogParser 解析日志
4. 使用 KnowledgeLearner 提取知识
5. 返回知识条目列表

#### 3. WebSocket 实时日志通道

使用 FastAPI 原生 WebSocket 支持。每个连接绑定一个 `source_id`（通过查询参数传递）。

```
Client → WebSocket /ws/logs?source_id=xxx&token=yyy
         → LogStreamService.on_message(source_id, line)
         → 缓冲区累积
         → 达阈值 → 后台线程：LogParser.parse → KnowledgeLearner.extract → KnowledgeStore.save
```

缓冲策略：
- 时间窗口：30 秒
- 行数阈值：100 行
- 先到者触发

#### 4. 日志源管理

新增 `log_sources` 数据表和 CRUD API，用于管理实时日志源的配置信息和状态。

### 错误处理策略

- 从任务学习：任务不存在 → 404；任务未完成 → 400（"任务状态不是 completed"）
- 从文件学习：文件类型不支持 → 400；LLM 调用失败 → 降级返回空列表 + warning
- WebSocket：连接认证失败 → close(4001)；source_id 无效 → close(4002)

- 操作：新增/编辑/删除日志源
- 连接状态：实时通过 WebSocket 心跳更新

| `knowledge`（已有） | 知识列表、统计、学习状态 |

在 `web/src/api/v2.ts` 的 `knowledgeApi` 中新增：
- `learnFromTask(taskId, options)` → `POST /knowledge/learn-from-task`
- `learnFromFile(file, options)` → `POST /knowledge/learn-from-file`

新增 `logStreamApi` 对象：
- `listSources()` → `GET /log-stream/sources`
- `createSource(data)` → `POST /log-stream/sources`
- `updateSource(id, data)` → `PUT /log-stream/sources/:id`
- `deleteSource(id)` → `DELETE /log-stream/sources/:id`
- `getSourceStats(id)` → `GET /log-stream/sources/:id/stats`

## 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| WebSocket 在 Nginx 反向代理后可能断开 | 实时日志通道不可用 | 配置 Nginx WebSocket 代理 + 前端自动重连 |
| 大量实时日志导致内存缓冲区溢出 | OOM | 设置缓冲区上限（1000行），超出时强制触发分析并清空 |
| LLM 调用耗时长，阻塞后续分析 | 知识提取延迟 | 使用线程池异步执行，与日志接收解耦 |
| 并发 WebSocket 连接过多 | 服务资源耗尽 | 限制最大连接数（默认 10），超出拒绝连接 |
