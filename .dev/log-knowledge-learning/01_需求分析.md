# 需求分析

## 基本信息

| 字段 | 值 |
|------|-----|
| 需求名称 | 日志文件知识学习 + 实时日志接入 |
| 需求类型 | FEATURE_UI |
| 影响范围 | 全栈 |
| 优先级 | P1 |
| 提出时间 | 2026-03-05 |
| 流转路径 | PM → 架构师 → UI设计师 → 后端开发 → 前端开发 → QA → DevOps → 交付 |

## 需求概述

扩展知识库学习能力，支持直接从已上传/已分析的日志文件中学习知识，并新增 WebSocket 实时日志接入通道，使系统能实时采集日志并自动提取知识，形成"日志采集 → 分析 → 知识提取 → 测试增强"的完整闭环。

## 详细描述

### 背景分析

当前系统知识库的学习路径为：
1. **手动输入文本**：用户在「从文本学习」对话框中粘贴文本内容 → 调用 `/api/v2/knowledge/learn` → LLM 提取知识
2. **日志上传后自动学习**：上传日志文件 → 后台解析请求/异常检测 → 完成后自动触发 `_trigger_knowledge_learning_from_requests` / `_trigger_knowledge_from_anomaly`
3. **API 文档导入自动学习**：导入 Swagger/Postman 文档 → 自动触发 `_trigger_knowledge_from_import`

**痛点**：
- 用户无法主动选择已有的日志分析任务来触发知识学习，必须重新上传或粘贴文本
- 自动学习是隐式的，用户无感知、无法控制
- 日志数据只能通过文件上传获取，无法接入实时日志流（如应用运行时的实时日志）

### 功能点列表

#### 阶段一：从日志文件/任务学习知识

1. **从已有分析任务学习知识**：在知识库页面新增「从日志学习」入口，用户可选择已完成的日志分析任务，一键触发知识提取
2. **上传日志文件直接学习**：在知识库页面支持直接上传日志文件（.log/.txt/.json），无需先到「日志洞察」页面上传，直接在知识库页面完成"上传 → 解析 → 提取知识"一站式流程
3. **学习结果可视化**：学习完成后展示提取的知识条目列表，包含标题、类型、置信度、来源，用户可选择性审核

#### 阶段二：实时日志接入

4. **WebSocket 实时日志通道**：后端新增 WebSocket 端点 `/ws/logs`，接受外部系统推送的实时日志行
5. **实时日志缓冲与批处理**：接收的日志按时间窗口（如 30 秒）或行数阈值（如 100 行）进行缓冲，达到阈值后触发一次日志分析
6. **实时日志连接管理页面**：前端新增实时日志连接配置页面，展示连接状态、已接收日志量、已触发分析次数等
7. **实时学习自动化**：实时日志分析完成后自动触发知识提取，新知识进入待审核队列
8. **日志源管理**：支持配置多个日志源（名称、WebSocket URL、标签），每个源独立管理

### 业务规则

1. 从已有任务学习知识时，任务状态必须为 `completed`
2. 上传日志文件学习知识复用现有的 LogParser 解析能力
3. 实时日志通道每个连接需要绑定一个日志源标识
4. 实时日志缓冲区满后触发分析，分析在后台线程池执行，不阻塞日志接收
5. 自动提取的知识默认状态为 `pending`（待审核），高置信度(>=0.8)可配置为自动通过
6. WebSocket 连接断开后自动重连（客户端侧），缓冲区中未处理的数据保持不丢失
7. 日志源的 `KnowledgeSource` 新增枚举值 `REALTIME_LOG` 用于区分来源

### 影响分析

- **前端影响**：
  - `KnowledgeList.vue`：新增「从日志学习」按钮和对话框
  - 新增 `LogSourceManage.vue` 页面（实时日志源管理）
  - `v2.ts` API 层：新增日志学习、日志源管理相关接口
  - 路由配置：新增日志源管理页面路由
- **后端影响**：
  - `knowledge.py` 路由：新增 `/knowledge/learn-from-task`、`/knowledge/learn-from-file` 接口
  - 新增 `log_stream.py` 路由：WebSocket 端点 + 日志源 CRUD
  - `KnowledgeLearner`：新增 `learn_from_task` 方法
  - `base.py` 枚举：`KnowledgeSource` 新增 `REALTIME_LOG`
  - 新增 `LogStreamService`：管理 WebSocket 连接、缓冲、触发分析
- **数据库影响**：
  - 新增 `log_sources` 表（日志源配置）
  - `KnowledgeSource` 枚举新增 `realtime_log` 值

## 验收标准

| 编号 | 验收条件 | 验证方式 |
|------|----------|----------|
| AC-1 | 知识库页面可选择已完成的日志分析任务，点击「学习」后成功提取知识条目 | 上传日志文件 → 分析完成 → 在知识库页面选择该任务 → 点击学习 → 知识列表出现新条目 |
| AC-2 | 知识库页面可直接上传日志文件进行知识学习 | 在知识库页面上传 .log 文件 → 等待处理 → 显示提取的知识条目 |
| AC-3 | 学习完成后展示知识提取结果，包含标题、类型、置信度 | 学习完成后弹出结果面板，列出每条知识的详细信息 |
| AC-4 | WebSocket 端点可接收实时日志推送 | 使用 wscat 连接 `/ws/logs` → 发送日志行 → 服务端正确接收并缓冲 |
| AC-5 | 实时日志达到缓冲阈值后自动触发分析 | 推送 100 行日志 → 观察后台触发一次分析任务 |
| AC-6 | 实时日志分析完成后自动提取知识 | 实时日志分析任务完成 → 知识库出现来源为 `realtime_log` 的新知识 |
| AC-7 | 日志源管理页面可配置、查看、删除日志源 | 在日志源管理页面 CRUD 操作正常 |
| AC-8 | 连接状态实时展示（已连接/已断开/已接收行数等） | 日志源管理页面展示各源的连接状态和统计信息 |

## 非功能需求

- **性能**：WebSocket 日志接收吞吐量 >= 1000 行/秒，不阻塞主事件循环
- **安全**：WebSocket 连接需验证 token（通过查询参数传递），防止未授权接入
- **可靠性**：日志缓冲区使用内存队列，服务重启时允许丢失未处理数据（v1 可接受）
- **兼容**：前端 WebSocket 使用原生 API，兼容主流浏览器

## 备注

- 阶段一（从日志文件/任务学习）为本次核心交付，阶段二（实时日志接入）作为增强功能一并设计和实现
- 现有的自动知识学习逻辑（`_trigger_knowledge_learning_from_requests` 等）保持不变，新增功能为用户主动触发的学习入口
- WebSocket 实时日志通道可作为后续对接 Kafka/Fluentd 等日志系统的基础
